## T7 modal dialog and focus (R4)

- `#lift` is `role="dialog"` `aria-modal="true"`, named after the window. Expand makes `#vp`, `#card` and `.mapbox`
  `inert`; Restore clears it and puts the focus on the Expand control (`view.navFocus`: no scroll, no reveal).
  Tab trap (capture on `#lift`): the dialog moves the focus itself between the window's stops, so WebKit's plain
  Tab (which skips buttons) also stays inside; in a tool or hosted-app area the app keeps Tab and only the edges
  wrap. Esc (bubble on `#lift`) restores unless the target is in a tool or hosted-app area or a control called
  `preventDefault()`. Shortcut against R4's text: a bubbling Esc handler, not a capture one. A capture handler cannot
  see a later `preventDefault()`, and hosted apps stop the key anyway, so the behaviour is as R4 says.
- New tests in `readme-expand.spec.ts`: R4.a (role, name, inert, 50 Tab and 50 Shift+Tab, Esc, focus back), R4.b
  (expanded CastleSiege: Esc stays in the game, Tab then Esc restores; a control that takes Esc). R4.c runs in T9.
