## Fable advisor decisions (2026-10-24), evidence in the session scratchpad `fable-009/`

1. **Drag jank.** Cause A: `.sheet-win` lacks the mock's `will-change: transform`; a scripted drag in Chromium
   headless (1280 × 800, dpr 2) gave 357 Paint events / 388 ms paint (with the line: 60 / 45; the mock: 91 / 15).
   Cause B: the held lean (|θ| up to 8.59° at ~600 px/s, up to 1.5° per frame) and the 1.03 lift scale resample
   every edge every frame ("motion blur"). Not a cause: frame pacing (Chromium p95 16.7 ms), fractional translate.
   Decision: `will-change: transform`; held = translate only (no lean, no scale); pin kick 4° → 2.5°, free ζ 0.34 →
   0.45. Simulated: capped throw peak 3.36° → 1.82°, settle 842 → 617 ms; Home from the far corner 4.33° → 2.34°.
2. **Music hint.** `os.ui.notify` is `console.info` on the sheet, so the hint was never visible. Decision: remove
   `musicHint` and its calls; no replacement. Text kept for later if a visible channel exists: "Music on. It follows
   your device volume. No sound? Click or tap inside the game once."
3. **404.** "4 0 4" as three small draggable windows on grid paper, sheet tokens and fonts, links work without JS,
   title "404 · RArgu OS", keyboard (arrows 24 px, Home, Enter/Space throw), reduced motion; draft 4.5 KB gzip.
4. **Phone mark.** Defect: with the card open the "area below the card" is 20 px high, so the mark jumps to the
   crawler. Decision: `mark()` uses the navigation area; opening/closing the card never changes the mark.
- Optional (not in 009): idle paints at zoom ≠ 100 % with demos on screen (250 Paint events in 4.3 s at 64 %);
  a 50 ms pickup frame from the lifted-shadow transition.

## T4 flake: quick-tools-music.spec.ts:212 (WebKit)

- **Symptom** (observed). `CI=1 npx playwright test tests/e2e/quick-tools-music.spec.ts:212 --project=webkit
  --repeat-each=20`: 1 failed, 19 passed. `page.evaluate: TypeError: undefined is not an object (evaluating
  'host.fs')`. It also failed once in each of two `e2e:all` runs.
- **Cause** (derived). The test read `window.__host` right after `page.goto()`, without a wait. `goto` waits for
  the load event only. `createHost()` sets `__host` (`src/sheet/host/load.ts:132`) after the lazy
  `import("./host/load")` in `host()` (`src/sheet/main.ts:178`). That import starts only when the first hosted
  window becomes eligible (`seen.watch`, `src/sheet/main.ts:326`), after the load event. Sometimes WebKit ran the
  test's evaluate first. This is a test defect, not a product defect: `__host` is set in the same synchronous
  step as the host's creation, before any app can start, so no app runs without the hook.
- **Fix.** `tests/e2e/quick-tools-music.spec.ts`: a new `hostHook(page)` (`page.waitForFunction(() => "__host"
  in window)`, no fixed sleep). `breakDemo`, `holdDemo` and the "R6.a demo read held" test call it before they
  use `__host`. These three were all the places in the file with this pattern. No product change. (The test is
  now at line 219.)
- **Results** (observed). `CI=1 npx playwright test tests/e2e/quick-tools-music.spec.ts:219 --project=webkit
  --repeat-each=40`: 40 passed. Same test, `--project=chromium --project=firefox --repeat-each=10`: 20 passed.
  Whole file, chromium + firefox + webkit: 36 passed. `npm run lint`: pass.
